# ADR-0003: Firestore για τις cloud λειτουργίες

- Κατάσταση: Accepted
- Ημερομηνία: 2026-09-02
- Πλήρες σκεπτικό: engineering log §5
- Σημείωση: γράφτηκε αναδρομικά στις 2026-09-07

## Πλαίσιο

Η εφαρμογή ξεκίνησε σκόπιμα χωρίς backend: οι ερωτήσεις είναι στατικές, η
βαθμολόγηση γίνεται στον browser, και το ιστορικό αποτελεσμάτων ζει στο
`localStorage`. Τρεις λειτουργίες όμως χρειάζονται κοινό, μόνιμο χώρο:
σύνδεση χρήστη, δημόσια Βαθμολογία μεταξύ παιδιών, και ανά-ερώτηση
ανατροφοδότηση (βαθμολογία 1–5 και αναφορά προβλήματος) που να μπορεί να
διαβαστεί για έλεγχο ποιότητας του περιεχομένου.

Το project δεν έχει προϋπολογισμό και δεν θέλει να συνδεθεί κάρτα πληρωμής. Ο
πληθυσμός χρηστών είναι μικρός — ένα παιδί και οι συμμαθητές του.

Εξετάστηκαν και απορρίφθηκαν δύο εναλλακτικές, με σκεπτικό που **είναι**
καταγεγραμμένο:

- **Supabase** στο δωρεάν επίπεδο: το project παγώνει μετά από περίοδο
  αδράνειας. Για μια εφαρμογή που ένα παιδί μπορεί να ανοίξει μετά από
  εβδομάδες, αυτό σημαίνει ότι η πρώτη επίσκεψη μετά τις διακοπές βρίσκει
  νεκρή υπηρεσία.
- **Firebase Data Connect / SQL**: κοστίζει μετά το trial.

## Απόφαση

Οι cloud λειτουργίες χτίζονται σε **Firebase**: Google sign-in για την
ταυτοποίηση, **Cloud Firestore** (περιοχή εντός ΕΕ) για τα δεδομένα, στο δωρεάν
πλάνο, χωρίς συνδεδεμένη κάρτα.

Το μοντέλο δεδομένων είναι τέσσερα collections: αθροιστικά ανά παίκτη για τη
Βαθμολογία, ένα έγγραφο ανά ολοκληρωμένο τεστ, ένα έγγραφο ανά ερώτηση για την
ανατροφοδότηση, και δύο βοηθητικά για το όριο εγγραφών.

Τρεις δεσμεύσεις συνοδεύουν την απόφαση και είναι μέρος της:

1. **Το SDK φορτώνεται δυναμικά** και μένει εκτός του main bundle· η αρχική
   φόρτωση της εφαρμογής δεν κατεβάζει Firebase.
2. **Το cloud είναι προσθετικό.** Όλα τα μονοπάτια αντέχουν απουσία
   ρυθμίσεων: χωρίς σύνδεση, η εφαρμογή λειτουργεί πλήρως με τοπικό ιστορικό.
3. **Το web config είναι δημόσιο εκ σχεδιασμού** — ταυτοποιεί το project, δεν
   το προστατεύει. Η προστασία στηρίζεται εξ ολοκλήρου στους κανόνες ασφαλείας
   και στα εγκεκριμένα domains.

Ως δικλείδα κόστους, μια πρώτη-φορά σύνδεση δεσμεύει μία από σταθερό αριθμό
θέσεων εγγραφής μέσα σε transaction· παλιός χρήστης περνά πάντα, και η διαγραφή
λογαριασμού ελευθερώνει τη θέση.

## Συνέπειες

Η υπηρεσία δεν παγώνει σε αδράνεια και δεν μπορεί να παραγάγει λογαριασμό προς
πληρωμή. Το αντίστοιχο κόστος είναι ότι η εξάντληση του δωρεάν quota **σταματά
τις λειτουργίες** αντί να τις χρεώσει· δεν υπάρχει ομαλή διαβάθμιση.

Η ασφάλεια των δεδομένων παιδιών στηρίζεται εξ ολοκλήρου στους κανόνες
ασφαλείας της βάσης, οι οποίοι συντάσσονται στην κονσόλα του παρόχου και
**δεν υπάρχουν μέσα στο repository**: χωρίς review, χωρίς ιστορικό, χωρίς
τρόπο επαναφοράς. Είναι η σοβαρότερη οφειλή που δημιουργεί αυτή η απόφαση.

Το όριο εγγραφών είναι **best-effort και client-side**. Δεν είναι εγγύηση
απέναντι σε κακόβουλο χρήστη· είναι φράγμα κόστους για μικρή, μη εχθρική βάση
χρηστών. Όταν γεμίσει, μια νέα σύνδεση απορρίπτεται — και το γεγονός δεν
φαίνεται πουθενά εκτός της κονσόλας.

Η δέσμευση «δυναμικά φορτωμένο SDK» πρέπει να επιβάλλεται σε κάθε μελλοντική
αλλαγή, και η παραβίασή της είναι **σιωπηλή**: ένα στατικό import σε κώδικα
αρχικής φόρτωσης δεν σπάει τίποτα ορατό, απλώς μεγαλώνει το bundle που
κατεβάζουν παιδιά σε κινητά.

Η επιλογή δένει την εφαρμογή με έναν συγκεκριμένο πάροχο στο επίπεδο του
κώδικα πρόσβασης δεδομένων. Επειδή όμως το cloud είναι προσθετικό και
απομονωμένο σε λίγα αρχεία, η αντικατάστασή του θα ήταν περιορισμένη σε έκταση
— όχι φθηνή, αλλά ούτε ξήλωμα της εφαρμογής.

Τέλος, η επιλογή του παρόχου έχει και **συνέπεια στο κείμενο προς τους
χρήστες**: η σελίδα απορρήτου περιγράφει τοποθεσία διακομιστών χωρίς να
κατονομάζει πάροχο. Αυτό ρυθμίζεται σε ξεχωριστό ADR.
